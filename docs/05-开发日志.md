# 05 · 开发日志

> 适用版本：**v0.1.0**
>
> 本文记录 v0.1.0 的开发过程：缺陷修复（现象 → 根因 → 解决方案）、功能新增、架构改进与版本迭代。
> 每条缺陷均通过**实跑复现**确认，非阅读代码的推测。

## 1. 版本概述

v0.1.0 是本项目**第一个正式稳定版**，基于对旧版全量排查结果重建。

| 维度 | 数量 |
|---|---|
| 缺陷修复 | 17 项 |
| 功能新增 | 21 项 |
| 架构改进 | 6 项 |
| 安全控制新增 | 12 项 |

采用 0.1.x 序列表示「功能可用、接口仍可能微调」，接口稳定后进入 1.0。

### 版本号锁定

版本号 `0.1.0` 在三处声明，升级版本时需同时修改：

- `pyproject.toml` → `version = "0.1.0"`
- `src/icogenerator/__init__.py` → `__version__ = "0.1.0"`
- `src/icogenerator/server.py` → `VERSION = "0.1.0"`

### B-01 多尺寸合并 ICO 100% 崩溃【致命】

**现象**：选择 ≥2 个尺寸并点击合并下载，弹窗提示 `生成多尺寸ICO失败：'ICO'`。

**根因**：旧版使用 `img.save(path, format='ICO', append_images=[...], save_all=True)`。`save_all=True` 要求格式已注册进 Pillow 的 `SAVE_ALL` 表，ICO 未注册，Pillow 10+ 抛 `KeyError: 'ICO'`。异常被 GUI 的 `except Exception` 吞掉，用户只看到一句无法理解的引号错误。

**解决方案**：改用 Pillow 官方支持的 `sizes=[...]` 参数，由 Pillow 在一次 save 中写入全部尺寸。

### B-02 多尺寸 ICO 静默丢弃大尺寸【严重】

**现象**：生成的 ICO 只包含 1–2 个尺寸，其余凭空消失且无任何报错。

**根因**：Pillow 的 ICO 插件会**静默跳过**所有大于基准图的尺寸。用 16px 基准图配 6 个目标尺寸，实测只写出 1 个。

**解决方案**：① 先把基准图升采样到最大目标边长，再交给 Pillow；② 编码后回读实际尺寸，缺失则抛异常，绝不交付残缺 ICO。

### B-03 拖拽含空格路径必然失败【严重】

**现象**：拖入 `C:\Users\me\My Pictures\logo.png` 提示「请选择有效的图片文件」，同一张图用按钮选择却正常。

**根因**：旧版用 `shlex.split(path)[0]` 解析拖拽路径。`shlex` 是 shell 词法分析器，反斜杠被当作转义符吃掉，`C:\Users\me\My Pictures\a.png` 被截成 `C:UsersmeMy`。

**解决方案**：改用 Tk 自带的 `tk.splitlist()`，正确处理空格与多文件拖入。

### B-04 CMYK / TIFF 源图预览崩溃【严重】

**现象**：用 CMYK JPEG 或 TIFF 作源图，点击后崩溃或预览空白。

**根因**：旧版直接 `img.save(temp_path)` 未做色彩模式转换，Pillow 无法把 CMYK 写成 PNG。

**解决方案**：在核心引擎统一先转为 RGBA，之后无论何种模式都不会再触发该问题。

### B-05 非正方形图片被强行拉伸变形【中等】

**现象**：用 16:9 照片生成 favicon，图标明显横向压扁。

**根因**：旧版直接 `img.resize(size, LANCZOS)`，把任意比例的图强行压成正方形。

**解决方案**：引入四种显式适配策略（cover / contain / maskable / stretch），默认 cover。

### B-06 硬编码图床凭据明文入库【中等 · 安全】

**现象**：源码中直接写着第三方图床的 uid / token，任何拿到源码的人都能直接使用该账户。

**根因**：旧版在 `ico_generator.py` 与 `test1.py` 中硬编码 32 位十六进制明文凭据。

**解决方案**：① 凭据移出源码，改为管理控制台显式配置；② 配置文件原子写入，POSIX 下权限 `0600`；③ 任何返回前端的配置走 `public_dict()` 脱敏；④ 日志中不打印凭据。

### B-07 静默上传用户图片，不可关闭【中等 · 隐私】

**现象**：每次选择图片，程序无条件上传到第三方图床，界面无开关、无提示。

**根因**：旧版 `upload_image` / `on_drop` 在加载成功后无条件调用上传函数。

**解决方案**：按本地优先模型重构——上传链路从核心流程中完全移除，结果先落本地目录，上传仅管理员显式配置后可手动或定时触发。

### B-08 临时文件污染工作目录【中等】

**现象**：无论从哪个目录启动，该目录都会出现 `temp_preview.png`、`temp_ico_files/` 等临时文件。

**根因**：旧版用相对路径写临时文件，从不同目录启动会散落一地，只读目录下直接崩溃，多实例并发时互相覆盖。

**解决方案**：预览改为纯内存渲染（`ImageTk.PhotoImage` 直接吃 BytesIO 还原的 PIL.Image），ZIP 直接在内存中打包，不再产生任何临时文件。

### B-09 缺少 tkinterdnd2 时程序无法启动【中等】

**现象**：未安装 tkinterdnd2 的环境，程序直接报错退出。

**根因**：旧版在模块顶层无条件 `from tkinterdnd2 import TkinterDnD, DND_FILES`，ImportError 直接中断启动。

**解决方案**：改为 try/except 可选导入，失败时降级为「点击选择文件」，并在日志中说明原因。

### B-10 批量下载临时目录异常残留【轻微】

**现象**：下载失败后 `temp_ico_files/` 目录残留在工作目录。

**根因**：旧版在 finally 中 rmtree，但进程被强杀则不会执行，且目录建在 CWD 下。

**解决方案**：移除临时目录方案，ZIP 直接在内存中打包。

### B-11 静态资源 404 导致前端完全失效【轻微】

**现象**：网页版页面能打开，但所有 JavaScript 都不执行，控制台无报错，网络面板能看到 404。

**根因**：`client.html` 引用 `app.js`，而实际文件名是 `client.js`。非模块脚本 404 不会在控制台报错，页面看起来完全正常，功能却全没了。

**解决方案**：改正引用，确保 HTML 中引用的静态资源文件名与实际一致。

### B-12 CLI 在 GBK 控制台崩溃【轻微】

**现象**：Windows GBK 控制台下执行 `icogen convert`，输出含 `✓` 的进度行时崩溃：`UnicodeEncodeError: 'gbk' codec can't encode character`。

**根因**：GBK 无法编码 `✓`（U+2713）等符号。

**解决方案**：`_make_console_safe()` 在每次输出前把 stdout/stderr 包成 UTF-8 + `errors="replace"`，包装操作幂等（打标记位避免重复包装）；`_print()` 对 `UnicodeEncodeError` 与 `ValueError` 均做兜底。

### B-13 桌面版预览图从未真正渲染【中等】

**现象**：界面所有功能正常，但预览区域始终是空的或显示「预览不可用」。

**根因**：v0.1.0 初版把预览改为纯内存渲染时，`ImageTk.PhotoImage` 传入了 `BytesIO` 而非 `PIL.Image` 对象，抛 `AttributeError: '_io.BytesIO' object has no attribute 'mode'`，被 `except Exception` 捕获后降级为「预览不可用」。功能表面上存在，实际从未生效。

**解决方案**：先用 `PIL.Image.open()` 把字节流还原为图像对象，再交给 `PhotoImage`。源图预览与结果预览两处均已修正。

### B-14 `icogen` 命令在部分 Windows 环境不可用【轻微】

**现象**：`pip install -e .` 显示成功，但执行 `icogen` 报「不是内部或外部命令」。

**根因**：非代码缺陷。用户级安装时脚本装到用户级 Scripts 目录，该目录不在 PATH 中。

**解决方案**：在部署教程中补充三种解决方案（临时加 PATH / 永久写入用户环境变量 / 直接用 `python -m icogenerator.cli`），并补充确认脚本位置的方法。

### B-15 CLI 错误分支自身崩溃【中等】

**现象**：命令行任何业务异常都不会得到应有的中文错误提示，而是先炸一个 `TypeError: _print() got an unexpected keyword argument 'file'`，真实错误原因被完全盖掉。

**根因**：`_print()` 的签名只有 `(text: str = "")`，但 `main()` 与 `cmd_convert` 共有 6 处调用传了 `file=sys.stderr`。这些分支只在出错时才走到，正常路径完全覆盖不到。

**解决方案**：`_print()` 增加 `err: bool = False` 关键字参数，在函数内部（包装之后）再解析目标流，6 处调用点同步改为 `err=True`。

### B-16 网页版「下载全部尺寸 (ZIP)」返回的不是 ZIP【中等】

**现象**：网页版「下载全部尺寸 (ZIP)」按钮下载到的文件内容是 ICO，用解压工具打开失败。

**根因**：前端为回避引入 JSZip，退而用合并 ICO 的 blob 冒充 ZIP。站点物料包是另一套产物，替代不了「每个尺寸一个独立 ICO」的需求。

**解决方案**：服务端新增 `POST /api/bundle`，复用 `build_ico_bundle()` 生成各尺寸独立 ICO，用标准库 `zipfile` 打包，产物与桌面版完全一致。

### B-17 两个网页均未声明 favicon【轻微】

**现象**：浏览器打开 `/app` 或 `/admin`，控制台固定出现一条指向 `/favicon.ico` 的 404。

**根因**：两个 HTML 的 `<head>` 都没有 `<link rel="icon">`，浏览器按惯例自动请求 `/favicon.ico`，服务端没有该路由。

**解决方案**：服务端新增 `GET /favicon.ico`，图案由本项目自己的引擎在内存中生成（`PIL.ImageDraw` 画「青瓷绿圆角方块 + 暖砂对勾」，`build_ico` 编码为 16/32/48 三尺寸 ICO），首次请求时构建并缓存。

## 3. 功能新增（21 项）

### N-01 命令行接口

新增 `icogen` 命令，子命令：`desktop` / `serve` / `convert` / `info` / `doctor`。
支持单文件与目录批量，尺寸支持 `16,32,48` 与 `16x16,32x32` 两种写法，全失败返回 `1`，部分成功返回 `0`。

### N-02 管理控制台（Web）

新增 `http://127.0.0.1:8765/admin`，包含令牌管理、对象存储配置（含测试连接）、定时自动上传、产物列表四个区块。凭据只回显掩码，令牌存 sessionStorage。

### N-03 对象存储上传（可选）

新增 S3 兼容上传，标准库实现 SigV4 签名，零第三方依赖。支持阿里云 OSS / 腾讯云 COS / 华为云 OBS / MinIO / AWS S3 / Cloudflare R2。

### N-04 定时自动上传

后台守护线程按间隔自动推送待上传产物，用 `Event.wait()` 而非 `sleep`，停止能立即响应。失败自动重试，超过次数标记为「上传失败」。

### N-05 手动上传与重试

产物列表每条支持单独上传，另有「立即上传全部待传」批量入口。已上传的产物幂等跳过，不会重复推送。

### N-06 尺寸预设

5 套预设（favicon / windows / full / small / mobile），新增尺寸 24×24 与 128×128。

### N-07 非正方形图片适配策略

四种策略：cover（居中裁切铺满）、contain（完整保留并留边）、maskable（PWA 安全区）、stretch（强制拉伸，兼容旧版）。

### N-08 EXIF 方向纠正

应用 `ImageOps.exif_transpose`，避免手机/相机拍摄的 JPEG 生成方向错误。EXIF 损坏时静默跳过。

### N-09 源图质量分析

生成接口同步返回源图质量分析：`will_upscale`、`opaque_source`、`cost`，供前端展示。

### N-10 站点物料包

13 文件站点物料包 ZIP：favicon.ico、apple-touch-icon、android-chrome、maskable 变体、mstile、manifest.json、browserconfig.xml、site-icon.html、MANIFEST.txt。

### N-11 网页版 Maskable 预览

生成结果区新增 maskable 安全区预览，帮助理解 Android/PWA 的图标安全区概念。

### N-12 网页版质量提示

结果区顶部按级别着色展示警告区，根据服务端返回的质量数据动态展示。

### N-13 分级质量提示

`core/quality.py` 把质量判断统一为带级别的结果（level / code / message），界面层只按级别着色，前端按 level 分流不匹配中文。

### N-14 maskable 安全区比例参数化

`normalize_to_square` 新增 `safe_zone` 参数，取值 0.50–1.00，默认 0.80，全链路透传。

### N-15 contain 补边颜色

`background` 参数在 contain 模式下真正生效：勾选「补边不透明」后留白取该颜色，不勾选则维持透明留边。

### N-16 站点物料包自说明清单

`MANIFEST.txt` 记录生成参数与每个文件的用途，物料包脱离生成环境后接收方仍能读懂。内容不含时间戳，同样输入输出字节一致。

### N-17 命令行预演与参数前置校验

`--dry-run` 在内存中生成并报告体积与警告，不落盘。`--background` / `--safe-zone` 非法值在生成前即失败。

### N-18 运行前环境自检 `icogen doctor`

报告 Pillow 版本、输出目录可写性、可选依赖状态、尺寸配置合法性与支持的输入格式。发现阻断性问题时退出码为 1。

### N-19 SVG 可选输入

`.svg` 经 `rasterize_svg()` 栅格化后接入同一套流水线。cairosvg 为可选依赖，未安装时给出明确提示。

### N-20 站点图标

`GET /favicon.ico` 由本项目引擎在内存中生成，图案与页面品牌标记一致。

### N-21 网页版「全部尺寸 ZIP」改由服务端打包

`POST /api/bundle` 返回真正的 ZIP，内含 `icon_{宽}x{高}.ico` 形式的单尺寸 ICO，与桌面版产物一致。

## 4. 架构改进（6 项）

| 编号 | 改进 | 说明 |
|---|---|---|
| A-01 | 核心逻辑与界面彻底分离 | `core/` 零 GUI、零网络、零磁盘，三套入口共用同一份核心实现 |
| A-02 | 统一异常体系 | `IcogenError` + 子类，每个异常可携带面向用户的 `hint` |
| A-03 | 本地存储作为真相源 | 原子写入 + SHA-256 + 元数据自愈 |
| A-04 | 配置管理 | 三层优先级 + 原子写入 + 权限收紧 + 统一脱敏 |
| A-05 | 本地 HTTP 服务 | 标准库 ThreadingHTTPServer，无 Web 框架依赖 |
| A-06 | 日志体系 | 标准库 logging，凭据绝不进日志，日志不可写时降级 |

### 统一异常体系

```
IcogenError
├── UnsupportedImageError    格式不支持
├── ImageDecodeError         内容损坏
├── ImageTooLargeError       像素超限（解压炸弹）
├── NoSizeSelectedError      未选尺寸
├── StorageError             本地读写失败
├── StorageConfigError       配置非法
└── UploadError              上传失败
```

调用方只需捕获 `IcogenError` 一个基类，GUI 与 HTTP 层都能把异常转成合适的用户提示。

## 5. 依赖变化

| 依赖 | 旧版 | v0.1.0 |
|---|---|---|
| Pillow | ✓ | ✓ |
| requests | ✓ | **移除**（标准库 SigV4 替代） |

缺任何一个都不影响核心生成链路。

## 6. 兼容性说明

v0.1.0 是重构版本，**不提供旧版数据格式兼容**：

- 旧版没有持久化的生成记录，无数据需要迁移；
- 旧版硬编码的图床凭据**未迁移**（安全考虑：凭据不应随版本流转；如需继续使用，请在管理控制台重新配置）；
- 配置格式全新，旧版无配置文件。
