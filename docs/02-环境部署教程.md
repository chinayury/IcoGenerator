# 02 · 环境部署教程

> 适用版本：**v0.1.0**

## 1. 环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| Python | ≥ 3.10 | 已在 3.14 验证 |
| 操作系统 | Windows / macOS / Linux | 桌面版需图形环境 |
| 必需依赖 | Pillow ≥ 10.0.0 | 唯一的运行时第三方库 |
| 可选依赖 | tkinterdnd2 ≥ 0.4.2 | 桌面版拖拽；不装则自动降级为点击选择 |
| 可选依赖 | ttkthemes ≥ 3.2.2 | 桌面版现代主题；不装则回退内置 clam 主题 |
| 可选依赖 | cairosvg ≥ 2.7.0 | SVG 输入；需系统 Cairo 库，不装则 SVG 给出明确提示 |

> 桌面版需要 Python 自带的 tkinter。Windows 官方安装包默认包含；
> 部分 Linux 发行版需单独安装 `python3-tk`。

## 2. 安装

### 方式一：直接运行源码（推荐用于试用）

```bash
# 1. 进入项目目录
cd /path/to/IcoGenerator

# 2. 创建虚拟环境（可选但建议）
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS / Linux

# 3. 安装依赖
pip install -r requirements.txt

# 4. 启动
python -m icogenerator.cli desktop
```

> 从源码目录直接运行时，需确保 `src` 在导入路径中。
> 用 `pip install -e .` 安装后则无需关心。

### 方式二：安装为命令行工具

```bash
pip install -e .

# 安装后可任意目录执行
icogen desktop
icogen serve
icogen info
icogen doctor
```

> ⚠️ **Windows 提示：`icogen` 提示「不是内部或外部命令」**
>
> 这是 Windows 的常见现象，不是安装失败。`pip install --user` 或系统 Python 权限不足时，
> 脚本会装到**用户级** Scripts 目录，而该目录未必在 PATH 中。实测本机路径：
>
> ```
> C:\Users\<用户名>\AppData\Roaming\Python\Python314\Scripts\icogen.exe
> ```
>
> 三种解决办法，任选其一：
>
> ```powershell
> # 方案 A：临时加入当前会话（立即生效）
> $env:PATH += ";$env:APPDATA\Python\Python314\Scripts"
>
> # 方案 B：永久加入用户环境变量
> [Environment]::SetEnvironmentVariable(
>   "Path",
>   [Environment]::GetEnvironmentVariable("Path","User") + ";$env:APPDATA\Python\Python314\Scripts",
>   "User")
>
> # 方案 C：直接用模块方式运行，无需 PATH
> python -m icogenerator.cli info
> ```
>
> 确认脚本实际位置：
>
> ```bash
> python -c "import sysconfig; print(sysconfig.get_path('scripts'))"
> ```
>
> 虚拟环境（venv）内的安装不受影响，激活后 `icogen` 直接可用。

### 可选安装增强依赖

```bash
pip install tkinterdnd2    # 桌面版拖拽
pip install ttkthemes      # 桌面版现代主题
pip install cairosvg       # SVG 输入（还需系统 Cairo）
```

未安装任何可选依赖时，核心功能完全不受影响，相关增强功能自动降级并给出提示。

### Linux 补装 tkinter

```bash
sudo apt install python3-tk
```

## 3. 目录与文件

首次启动会自动创建以下内容：

| 路径 | 内容 |
|---|---|
| `%LOCALAPPDATA%\icongenerator\config.json`<br>（Linux: `~/.config/icongenerator/config.json`） | 配置与凭据 |
| `~/icongenerator/output/` | **生成结果真相源** |
| `~/icongenerator/output/icons/` | 单个 ICO |
| `~/icongenerator/output/bundles/` | ZIP 打包 |
| `~/icongenerator/output/.icogen/index.json` | 产物元数据 |
| `%LOCALAPPDATA%\icongenerator\desktop.log` | 桌面版运行日志 |

查看实际路径：

```bash
icogen info
```

## 4. 配置说明

配置文件为 JSON，首次启动自动生成默认值。

```json
{
  "output_dir": "C:/Users/你的用户名/icongenerator/output",
  "host": "127.0.0.1",
  "port": 8765,
  "storage": {
    "enabled": false,
    "endpoint": "",
    "region": "",
    "bucket": "",
    "access_key": "",
    "secret_key": "",
    "prefix": "icongenerator",
    "path_style": true,
    "use_ssl": true,
    "timeout": 30
  },
  "scheduler": {
    "enabled": false,
    "interval_minutes": 30,
    "batch_size": 50,
    "max_retries": 3
  }
}
```

**默认全部关闭上传功能**——遵循最小权限原则，不主动向任何外部服务发送数据。

### 环境变量覆盖

便于服务化部署，优先级高于配置文件：

```bash
# Windows PowerShell
$env:ICOGEN_OUTPUT_DIR = "D:\icons"
$env:ICOGEN_PORT = "9000"
$env:ICOGEN_STORAGE_ENABLED = "true"
$env:ICOGEN_ENDPOINT = "https://oss-cn-hangzhou.aliyuncs.com"
$env:ICOGEN_BUCKET = "my-bucket"
$env:ICOGEN_ACCESS_KEY = "..."
$env:ICOGEN_SECRET_KEY = "..."
```

支持的变量：`ICOGEN_OUTPUT_DIR`、`ICOGEN_HOST`、`ICOGEN_PORT`、
`ICOGEN_STORAGE_ENABLED`、`ICOGEN_ENDPOINT`、`ICOGEN_REGION`、`ICOGEN_BUCKET`、
`ICOGEN_ACCESS_KEY`、`ICOGEN_SECRET_KEY`、`ICOGEN_PREFIX`、`ICOGEN_PATH_STYLE`、
`ICOGEN_USE_SSL`、`ICOGEN_TIMEOUT`、`ICOGEN_SCHEDULER_ENABLED`、`ICOGEN_SCHEDULER_INTERVAL`。

## 5. 启动后台服务（网页版 + 管理控制台）

```bash
icogen serve
```

输出示例：

```
IcoGenerator 后台服务已启动：http://127.0.0.1:8765
管理员令牌：xxxxxxxxxxxxxxxx
按 Ctrl+C 退出
```

**令牌每次启动随机生成**，仅打印一次，请妥善保存。

访问地址：

| 地址 | 用途 | 是否需要令牌 |
|---|---|---|
| `http://127.0.0.1:8765/app` | 网页版生成器 | 否 |
| `http://127.0.0.1:8765/admin` | 管理控制台 | 是 |
| `http://127.0.0.1:8765/api/health` | 健康检查 | 否 |

指定地址与端口：

```bash
icogen serve --port 9000
```

### 关于暴露到局域网

默认绑定 `127.0.0.1`。若确需局域网访问：

```bash
icogen serve --host 0.0.0.0 --port 8765
```

⚠️ **务必知悉**：管理接口在任何绑定地址下都要求 Bearer 令牌，但本项目**未内置 HTTPS**。
暴露到非本机网络前，请自行在前面加反向代理并启用 TLS，或使用 SSH 隧道：

```bash
ssh -L 8765:127.0.0.1:8765 user@server
# 然后在本地浏览器访问 http://127.0.0.1:8765
```

## 6. 接入对象存储（可选）

### 6.1 支持的存储

任何 S3 兼容的对象存储：

- 阿里云 OSS
- 腾讯云 COS
- 华为云 OBS
- MinIO
- AWS S3
- Cloudflare R2

### 6.2 配置步骤

1. 启动服务，打开 `http://127.0.0.1:8765/admin`
2. 粘贴令牌，点「连接」
3. 在「对象存储配置」中填写：

| 字段 | 说明 | 各服务取值 |
|---|---|---|
| Endpoint | 服务地址 | OSS: `https://oss-cn-hangzhou.aliyuncs.com`<br>COS: `https://cos.ap-guangzhou.myqcloud.com`<br>MinIO: `http://127.0.0.1:9000` |
| Region | 区域 | OSS: `oss-cn-hangzhou`<br>S3: `us-east-1` |
| Bucket | 存储桶名 | 你创建的桶 |
| Access Key / Secret Key | 访问密钥 | 在控制台获取 |
| 寻址方式 | path-style | **MinIO 必选**；OSS/COS/S3 一般选 virtual-host |
| 使用 HTTPS | 加密 | 公网务必开启 |

4. 点「保存配置」→ 点「测试连接」

> ⚠️ **安全提醒**：Access Key 应使用**只授予目标桶写权限**的子账号，
> 不要使用主账号密钥。本工具不会把凭据写入日志，页面也只回显掩码
> （如 `AKIA******MPLE`）。

### 6.3 上传方式

**手动上传**

- 在产物列表点某个文件的「上传」
- 或点「立即上传全部待传」

**定时自动上传**

1. 在「定时自动上传」勾选「启用定时任务」
2. 设置间隔（分钟）、单批数量、失败重试次数
3. 点「保存调度配置」，再点「启动」

调度线程在服务进程内运行，服务停止即停止。失败会自动重试，超过重试次数标记为「上传失败」，可在页面上手动重试。

### 6.4 对象路径规则

上传后的对象路径为：

```
{prefix}/{年}/{月}/{日}/{文件名}
例：icongenerator/2026/10/11/favicon.ico
```

按日期分层，避免单目录对象过多。

## 7. 服务器 / 无图形环境部署

SSH、容器等无图形环境下桌面版无法启动，请使用 CLI：

```bash
# 单文件
icogen convert logo.png -s 16,32,48,256

# 批量目录（逐个文件单独生成 ICO）
icogen convert ./images/ -s 16,32,48,256 -o /var/www/icons

# 指定非正方形处理策略
icogen convert logo.jpg -s 16,32,48 --fit contain
```

退出码：全部成功 `0`，全部失败 `1`。

## 8. Docker 部署（容器）

项目根目录提供 `Dockerfile` 与 `docker-compose.yml`，镜像内仅安装 Pillow 运行时依赖。

```bash
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8765/api/health
```

- 默认映射宿主 `8765` 端口，容器内监听 `0.0.0.0:8765`。
- 生成结果持久化在命名卷 `icogenerator-data`（容器内 `/data/output`）。
- 管理令牌在容器启动日志中打印：`docker compose logs icogenerator | grep 管理员令牌`。
- 升级：`docker compose up -d --build`。
- 容器以非 root 用户（uid 10001）运行，并移除全部 Linux capabilities。

> 容器同样不内置 HTTPS。对外暴露时请在反向代理层启用 TLS，
> 或仅绑定回环地址并通过 SSH 隧道访问。

## 9. 常见问题

**Q: 桌面版启动报 `ModuleNotFoundError: No module named 'tkinterdnd2'`**

v0.1.0 已把拖拽改为可选，出现此提示说明环境中有残留的旧代码。
确认使用的是新版：`python -m icogenerator.cli --version` 应输出 `icogen 0.1.0`。

**Q: 生成的多尺寸 ICO 只有最小的那几个尺寸**

这是旧版的 bug（Pillow 静默丢弃大尺寸）。新版已修复并加了回读校验，
若仍出现请确认代码版本。

**Q: 图标是变形的**

非正方形源图请选择处理策略：

- `cover` 居中裁切铺满（推荐 favicon，不变形但会裁掉边缘）
- `contain` 完整保留并留边（不变形且不裁切，四周留白）
- `maskable` PWA 安全区（内容缩到中心安全区，可被裁成任意形状）
- `stretch` 强制拉伸（会变形，仅为兼容旧版）

**Q: 端口被占用**

```bash
icogen serve --port 9000
```

**Q: 忘了管理令牌**

重启服务会生成新令牌。

**Q: 桌面版在 SSH 里启动报错**

无图形环境不支持 GUI，请改用 `icogen serve` 或 `icogen convert`。

**Q: SVG 文件无法使用**

SVG 输入需要可选依赖 cairosvg，且需系统安装 Cairo 库。
安装后即可使用，未安装时其他格式完全不受影响。
