# 04 · 安全设计说明

> 适用版本：**v0.1.0**
>
> 本文说明 IcoGenerator v0.1.0 的安全架构设计与已落地的安全控制。
> 所有结论均经动态验证（实跑脚本或浏览器实测）确认，非静态阅读推断。

## 1. 安全设计总览

v0.1.0 基于旧版全量排查重建，修复了旧版的高危与中危问题，并新增多项安全控制。
核心安全理念：**本地优先、最小权限、纵深防御**。

| 维度 | 旧版状态 | v0.1.0 状态 |
|---|---|---|
| 凭据管理 | 硬编码明文入库 | 移出源码，配置文件原子写入 + 权限收紧 + 全程脱敏 |
| 图片上传 | 静默上传第三方图床，不可关闭 | 本地优先，上传仅管理员显式配置后可手动/定时触发 |
| 文件路径 | 路径穿越可写出目录外 | 文件名白名单净化 + 解析后越界检查双重防护 |
| 接口鉴权 | 管理接口鉴权缺失 | 管理接口始终要求 Bearer 令牌，不因绑定回环而放宽 |
| CSRF 防护 | 无 | 校验 Origin + 强制 application/json |
| 依赖安全 | requests + tkinterdnd2 | 运行时仅 Pillow，移除 requests；可选依赖均为「装了增强、没装降级」 |

## 2. 凭据管理

### 2.1 源码零密钥

源码内**不存放任何密钥**。access_key / secret_key 只存在于用户配置文件中，
首次启动自动生成默认配置（全部留空），遵循最小权限原则。

### 2.2 配置文件安全

- **原子写入**：先写同目录临时文件，再 `os.replace` 替换，避免写入中途崩溃导致配置损坏；
- **权限收紧**：POSIX 下设为 `0600`（仅当前用户可读写）；Windows 上依赖用户账户 ACL 隔离；
- **损坏回退**：配置文件解析失败时回退默认值并记录日志，不阻断启动。

### 2.3 脱敏

任何返回给前端或写入日志的配置都走 `public_dict()` 脱敏：

- 保留首尾各 4 位，中间用 `*` 替代；
- 短凭据（≤8 位）整体打码，避免因长度不足反而泄露；
- 前端页面只显示掩码（如 `AKIA******MPLE`），不回显原文；
- 修改凭据时，输入框留空表示「不修改」已有值，避免掩码被回写覆盖真实密钥。

## 3. 本地优先与隐私

### 3.1 不配置存储也能 100% 使用

生成、导出、打包全部不依赖网络。所有结果先落本地目录，功能至此已完整可用。
对象存储未配置时，上传队列直接返回「对象存储未启用」，本地文件完好无损。

### 3.2 上传链路从核心流程移除

旧版在**每次用户选择图片时**无条件上传到第三方图床。v0.1.0 将上传链路从核心生成流程中完全移除，
仅在管理员显式配置对象存储后，可手动或定时触发上传。用户图片不会在无感知的情况下离开本机。

## 4. 文件路径安全

### 4.1 文件名白名单净化

`sanitize_filename()` 对任何写入磁盘的文件名进行净化：

1. 剥离目录部分（兼容 Windows `\` 与 POSIX `/`）；
2. 去除控制字符（`\x00-\x1f`、`\x7f`）；
3. 仅保留 `[A-Za-z0-9._-]`，其余替换为 `_`；
4. 拦截 `.` / `..` 特殊名；
5. **扩展名白名单**：仅 `.ico` / `.png` / `.zip` / `.json`，`.exe` 等一律改写为 `.ico`，杜绝写出可执行文件；
6. 长度限制（stem ≤ 80 字符）。

实测验证：

```
'../../evil.ico'          -> 'evil.ico'      PASS
'..\..\win\evil.ico'      -> 'evil.ico'      PASS
'payload.exe'             -> 'payload.ico'   PASS  (扩展名被改写)
'a/b/c.png'               -> 'c.png'         PASS  (目录被剥离)
```

### 4.2 解析后越界检查

即便净化被绕过，`_safe_path()` 在解析后检查路径是否位于基目录内，越界即拒绝：

```python
candidate = (base / safe_name).resolve()
candidate.relative_to(base.resolve())  # 越界则抛 ValueError
```

### 4.3 静态资源白名单

服务端静态资源采用**固定文件名 + 固定 MIME** 白名单，不接受用户传入路径：

```
/../config.py        -> 404 PASS
/%2e%2e/server.py    -> 404 PASS
/web/../../server.py -> 404 PASS
/..%2fconfig.py      -> 404 PASS
```

## 5. 接口鉴权与 CSRF

### 5.1 管理接口始终鉴权

**回环地址不视为鉴权边界**——同机任意进程、以及用户浏览器里任意网页发出的跨站请求都能打到回环。
因此，所有管理接口（配置、上传、下载）**始终**要求 Bearer 令牌，**不因绑定 127.0.0.1 而放宽**。

- 令牌随机生成（`secrets.token_urlsafe(32)`），只存内存，每次启动变化；
- 鉴权使用 `secrets.compare_digest` 常数时间比较，避免时序侧信道；
- 前台 `/api/generate` 无需令牌，但它只写本地磁盘、不改任何配置。

### 5.2 CSRF 防护

- **Origin 校验**：带 Origin 且非同源（127.0.0.1 / localhost / ::1）的请求一律拒绝，防止恶意网页借用户浏览器调用本机服务；
- **Content-Type 强制**：POST 请求必须显式声明 `application/json`，不放行空 Content-Type，杜绝跨站简单表单请求触发。

### 5.3 请求体防护

- **请求体大小上限**：20MB，防止内存耗尽；超限前先排空请求体再拒绝，避免连接复用问题；
- **响应体读取上限**：上传响应最多读取 8KB，防止异常服务端返回超大内容打满内存；
- **JSON 解析失败转 400**：客户端发来的畸形请求属于客户端错误，不冒泡成 500。

## 6. 对象存储上传安全

### 6.1 标准库实现 SigV4

用标准库实现 AWS Signature V4 签名，无需 boto3 / requests，减少供应链风险面。
签名可被独立重算复现，请求头与错误信息中均不含密钥。

### 6.2 受限 Opener

上传走**受限 opener**，仅注册 HTTP / HTTPS 与重定向护栏：

- 默认 opener 中的 FTP / File / Data / 环境代理等面整体关闭；
- 重定向目标协议二次校验，仅放行 http / https；
- 对象 URL 组装后再次做协议白名单校验，阻断任何路径把请求引向非 HTTP 协议。

### 6.3 Content-Type 白名单

上传使用固定 Content-Type，不从用户输入推导，避免头部注入：

| 扩展名 | Content-Type |
|---|---|
| `.ico` | `image/x-icon` |
| `.png` | `image/png` |
| `.zip` | `application/zip` |
| `.json` | `application/json` |

## 7. 解压炸弹防护

解码前进行多层检查：

| 检查项 | 上限 | 说明 |
|---|---|---|
| 单边像素 | 8192 | 超过则拒绝解码 |
| 总像素 | 178,956,970 | 约 1.69 亿，与 Pillow 自身保护阈值一致 |
| Pillow DecompressionBombError | — | 捕获并转业务异常 |

网页版前端也做一道预检（单边 > 8192 或总像素 > 4000 万），减少无效请求。

## 8. 输入校验全面化

所有用户输入在进入核心逻辑前均做校验，非法值在生成前即失败：

| 输入 | 校验 |
|---|---|
| 尺寸 | 必须在 1–256 之间；空列表报明确错误 |
| `fit_mode` | 白名单 cover / contain / maskable / stretch |
| `safe_zone` | 必须在 0.50–1.00 之间，越界即失败 |
| `background` | 必须是 6 位十六进制，非法即失败 |
| `timeout` | 1–300 秒 |
| `interval_minutes` | 1–1440 |
| `batch_size` | 1–1000 |
| `max_retries` | 0–10 |
| `port` | 1–65535 |
| `endpoint` | 必须 http:// 或 https:// 开头 |
| JSON 体 | 解析失败转 400，不冒泡成 500 |

## 9. 降级策略

所有可选依赖均为「装了增强、没装降级」，缺任何一个都不影响核心生成链路：

| 场景 | 行为 |
|---|---|
| 未装 tkinterdnd2 | 拖拽不可用，点击选择正常，日志说明 |
| 未装 ttkthemes | 主题降级到 clam，功能不受影响 |
| 未装 cairosvg | SVG 输入给出明确提示，其他格式不受影响 |
| 无图形环境 | 明确报错并提示改用 serve / convert |
| 未配置对象存储 | 完全本地运行，生成导出不受影响 |
| 元数据损坏 | 备份后重建，不阻断使用 |
| 日志不可写 | 降级为仅控制台 |

## 10. 安全响应头

服务端所有 JSON 响应携带：

- `X-Content-Type-Options: nosniff` — 禁止浏览器 MIME 嗅探；
- `Referrer-Policy: no-referrer` — 不泄露来源信息；
- `Cache-Control: no-store` — 禁止缓存敏感响应。

## 11. 安全结论

v0.1.0 **未发现高危或中危漏洞**。旧版的 3 项高危 / 5 项中危问题全部修复，
新增 12 项安全控制，覆盖凭据管理、路径防护、接口鉴权、CSRF、解压炸弹、输入校验等维度。
所有安全控制均有对应实现，核心逻辑与界面彻底分离，便于独立审查与验证。
