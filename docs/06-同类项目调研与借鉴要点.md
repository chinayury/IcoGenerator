## 二、深筛结论与可借鉴要点清单

### A. pwa-asset-generator（3043★，领域标杆）—— 已借鉴 2 项

| # | 要点 | 本项目落地方式 |
|---|---|---|
| A1 | **通用内容留白（默认 10% padding）**：所有输出默认给主体四周留出呼吸空间，可调 | v0.1.1 核心引擎新增 `padding` 参数（0–0.6），cover / contain 模式内容缩至 `(1-padding)` 居中；CLI `--padding`、Web API `padding` 字段、网页版与桌面版控件全链路打通 |
| A2 | **CLI 是库的薄封装**：`pwa-asset-generator` 命令只是模块 API 的 wrapper，能力全在库层 | 已有 core 分层与此一致；本轮把 CLI 补齐到与 Web 同能力（站点物料包，见 B1），保持「CLI 也是一等入口」 |
| A3 | manifest.json / index.html 自动改写注入 | 采纳保守变体：`merge_manifest()` 只合并 icons 数组、保留用户其余字段（CLI `--merge-manifest`），不做 HTML 改写 |

### B. vite-pwa/assets-generator（Vite PWA 官方）—— 已借鉴 1 项

| # | 要点 | 本项目落地方式 |
|---|---|---|
| B1 | **CLI-first 定位 + 预设（minimal2023Preset）**：一条命令产出全部 PWA 物料，零配置可用 | `icogen convert --site-assets` 一条命令产出完整站点物料 ZIP（CLI 此前只有 ICO 输出，是四入口能力空档） |

### C. ruisaraiva19/favycon —— 已借鉴 1 项

| # | 要点 | 本项目落地方式 |
|---|---|---|
| C1 | **SVG favicon 透传**：源图为矢量时同时产出 `favicon.svg` 并加 `<link rel="icon" type="image/svg+xml">`，现代浏览器直接用矢量渲染 | `build_site_assets(source_svg=...)`：源图是 SVG 时物料包附带 favicon.svg；HTML 片段与 `describe_site_assets()` 相应更新 |

### D. duma520/Image_To_Icon_Converter（Python 直接同类）—— 已借鉴 1 项

| # | 要点 | 本项目落地方式 |
|---|---|---|
| D1 | **高 DPI 感知在窗口创建前设置**（QApplication 前置 `AA_EnableHighDpiScaling`） | 桌面版 `main()` 在 `tk.Tk()` 之前调用 `SetProcessDpiAwareness(1)`，高 DPI 屏文字/图标不再模糊 |
| D2 | 设置实时持久化 + 版本迁移标记（`sizes_exact`） | 已有等价实现（UiPreferences 全字段保存恢复），无需改动 |
| D3 | 转换历史 SQLite | 已有等价实现（本地制品索引 index.json），无需改动 |

### E. sprout2000/elephicon（桌面 GUI 对标）—— 结论：无增量

偏好持久化（electron-store）已有等价实现；ICNS 输出超出本项目 ICO 定位，不采纳。

### F. jaretburkett/electron-icon-maker —— 结论：无增量

多平台目录结构（icons/win、icons/mac）适配的是应用打包场景；favicon 物料包需平铺在站点根目录，保持现状。

## 三、顺带整改项（调研中发现）

| # | 问题 | 整改 |
|---|---|---|
| X1 | 版本号散落 7 处（含 client.html / index.html 标题、cli.py 描述），每次发版易漏改 | 收敛为单一来源：`__init__.py` 声明，server.py / desktop.py 导入；HTML 标题与徽章改由前端从 `/api/health` 动态填充 |
| X2 | 桌面版界面偏好缺 padding 字段 | UiPreferences 增加 `padding` 并随生成参数持久化 |

## 四、取舍原则备忘

- 只采纳与本仓库「运行时仅依赖 Pillow、四入口共用 core、本地优先」约束相容的要点；
- 平台专有扩展（ICNS、启动屏、暗色模式变体）暂不采纳，避免定位膨胀；
- 涉及改写用户既有文件的能力（HTML 注入）一律收敛为显式、可回退的最小操作（仅 manifest 合并、仅 CLI 显式参数触发）。
