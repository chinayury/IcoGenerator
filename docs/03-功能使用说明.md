# 03 · 功能使用说明

> 适用版本：**v0.1.0**

## 1. 桌面版 GUI

启动：

```bash
icogen desktop
# 或
python -m icogenerator.cli desktop
```

### 1.1 导入源图

两种方式：

- **点击**：点虚线区域或「选择图片文件」按钮
- **拖拽**：把图片拖到虚线区域（需安装 `tkinterdnd2`）

支持格式：JPG / JPEG / PNG / GIF / BMP / WebP / TIFF / ICO / SVG（需 cairosvg）

> 路径含空格的图片（如 `C:\Users\me\My Pictures\logo.png`）拖拽可正常识别。
> 一次拖入多个文件时，仅处理第一个并在状态栏提示。

选图成功后：

- 上传区显示文件名与原始尺寸
- 「生成 ICO 文件」按钮变为可用
- 右侧显示源图预览

### 1.2 定制输出规格

**预设方案**（下拉框 + 「应用」）：

| 预设 | 尺寸 |
|---|---|
| 网站 favicon | 16 / 32 / 48 |
| Windows 程序图标 | 16 / 24 / 32 / 48 / 64 / 256 |
| 完整尺寸集 | 16 / 24 / 32 / 48 / 64 / 128 / 256 |
| 轻量 | 16 / 32 |
| 移动端 / PWA | 48 / 64 / 128 / 256 |

也可直接勾选单个尺寸，或用「全选」「取消全选」。

### 1.3 非正方形图片处理

当源图不是正方形（如 16:9 照片）时，必须选择处理方式，否则会变形：

| 模式 | 行为 | 适用 |
|---|---|---|
| **cover**（默认） | 等比放大后居中裁切铺满 | favicon、应用图标——**推荐**，不变形 |
| **contain** | 等比缩小后居中留边 | 需要完整保留画面内容 |
| **maskable** | 内容缩到中心安全区，四周留出可被裁切余量 | PWA / Android 自适应图标 |
| **stretch** | 强制拉伸成正方形 | 仅在必须保留旧版行为时使用 |

### 1.4 安全区比例与补边颜色

适配策略下方有两个参数，只对需要补边的模式生效：

| 参数 | 作用 | 取值范围 |
|---|---|---|
| 安全区比例 | maskable 模式下主体内容占中心的比例 | 0.50 – 1.00，默认 0.80 |
| 留白颜色 | contain / maskable 的补边底色，6 位十六进制 | 如 `#112233` |
| 补边不透明 | contain 补边是否使用该颜色（不打勾则透明留边） | 开关 |

两者的非法值在点「生成」前就会弹出提示，不会产出不可用的结果。
cover 与 stretch 模式没有补边，这两个参数不影响结果。

关于安全区比例：MDN 把安全区定义为「直径等于图标最小边 80% 的**圆**」，
而业界通行做法（pwa-asset-generator 等）取四边各留 10%，即 80% 的**正方形**。
后者对「内容顶到自身四角」的图仍可能被圆形遮罩裁到。默认 0.80 与业界一致；
若图标主体是占满四角的图形，可调到 0.5–0.6 并在构图上把主体收回中心。

### 1.5 生成与导出

点「生成 ICO 文件」。成功后：

- 右侧显示各尺寸预览缩略图
- 自动保存一份到本地输出目录
- 导出按钮变为可用：

| 按钮 | 产出 |
|---|---|
| 保存多尺寸 ICO | 单个 `.ico`，内含全部选中尺寸（**给 favicon 用**） |
| 保存全部尺寸 (ZIP) | ZIP 包，内含每个尺寸的独立 `.ico`（给需要单尺寸的场景用） |
| 保存站点物料包 (ZIP) | 13 文件站点物料包（ICO + apple/android/mstile/manifest/html 片段 + MANIFEST.txt） |
| 可读性检查 | 按**实际像素**展示 16/32/48，并附 4 倍最近邻放大图 |
| 打开输出目录 | 直接打开本地输出文件夹 |

物料包 ZIP 内的 `MANIFEST.txt` 记录了本次使用的全部参数（源图尺寸、适配策略、
安全区比例、留白颜色、ICO 尺寸、应用名、主题色）与每个文件的用途。把 ZIP 转交他人时，
对方不需要再来问「这些文件是干什么的、用什么参数生成的」。

### 1.6 可读性检查

主预览区为了看得清会把图放大，因此看不到小尺寸下的真实观感。
点「可读性检查」会弹出对照窗口：左半是按 16×16 / 32×32 / 48 的**真实像素**渲染，
右半是同尺寸的 4 倍最近邻放大（只用于看清像素块，不代表真实效果）。

若左半的 16×16 已经糊成一团，说明该尺寸下不可用——要么换更大的源图，
要么减少图标细节。这与质量提示区的「源图较小，以下尺寸会被放大」是同一件事的
两个视角：提示说明风险，对照窗口让风险可见。

### 1.7 质量提示

生成区下方的提示区按级别着色，内容由核心层统一计算后展示：

| 级别 | 触发条件 |
|---|---|
| 注意（warning） | 源图小于目标尺寸需放大；源图无透明通道；单边或总像素逼近解码上限；选中尺寸超过 4 个；ICO 超过 32KB 软预算 |
| 提示（info） | ICO 体积接近 32KB 软预算 |
| 正常（success） | 以上都不命中，给出源图尺寸与透明通道结论 |

提示只提醒、不阻断——用户可能确实只需要一个小图标。

### 1.8 状态栏

底部状态栏实时提示当前状态：就绪 / 已载入 xxx / 生成中 / 生成完成 / 错误原因。

## 2. 网页版

启动服务后访问：

```
http://127.0.0.1:8765/app
```

页面左栏顶部显示服务状态：

- 绿色「服务已就绪 v0.1.0」——正常
- 红色「未连接到本地服务」——服务未启动，先运行 `icogen serve`

操作步骤与桌面版基本一致：选图 → 选尺寸 → 选处理策略 → 生成 → 下载。

网页版独有功能：

- **maskable 选项**：尺寸区下方有「站点物料包包含 maskable 安全区变体」复选框，生成结果区会展示安全区预览；
- **安全区比例与留白颜色**：与桌面版同名的两个输入框，语义完全一致；
- **分级质量提示**：结果区顶部按级别着色（注意 / 提示 / 正常），文案由服务端 `hints` 字段下发，前端不自行拼装；
- **实际像素对照**：结果区在放大预览下方额外给出一排 1:1 瓦片（≤48 的尺寸），直接回答「缩到这么小还能认出吗」；
- **站点物料包**：结果区新增「下载站点物料包 (ZIP)」按钮，可导出 13 文件站点物料包（含 MANIFEST.txt，需管理员令牌）。

> 网页版的图片会发送到**本机** 127.0.0.1 服务处理，不会上传到外部服务器。
> 页面左栏也标注了这一点。

两个页面的浏览器标签图标（`/favicon.ico`）由本项目自己的引擎在内存中生成，
图案与页面左栏的品牌标记一致，输出为 16 / 32 / 48 三尺寸 ICO。该路由只认
`/favicon.ico` 这一个字面路径，其他变体一律返回 404。

前端会先做一次预检，拦截明显不合法的输入：

- 文件类型（非图片）
- 文件大小（> 20MB）
- 图片尺寸（单边 > 8192px 或总像素 > 4000 万）

## 3. 管理控制台

访问 `http://127.0.0.1:8765/admin`，需输入令牌（服务启动时打印）。

未连接令牌前，下方卡片为锁定状态（不可点击）。

### 3.1 云端存储配置

填写并保存后，点「测试连接」验证。

| 字段 | 必填 | 说明 |
|---|---|---|
| 启用上传 | — | 勾选后前台生成的产物才会上传 |
| Endpoint | 是 | 必须以 `http://` 或 `https://` 开头 |
| Region | 否 | 留空默认 `us-east-1` |
| Bucket | 是 | 存储桶名 |
| Access Key | 是 | 留空表示**不修改**已有值 |
| Secret Key | 是 | 留空表示**不修改**已有值 |
| 路径前缀 | 否 | 默认 `icongenerator` |
| 寻址方式 | — | MinIO 选 path-style；OSS/COS/S3 选 virtual-host |
| 使用 HTTPS | — | 公网务必开启 |
| 超时 | — | 1–300 秒 |

> 凭据保存后页面只显示掩码（如 `AKIA******MPLE`），不会回显原文。
> 需要修改时重新输入；不填则保持原值。

### 3.2 自动上传调度

| 字段 | 范围 | 说明 |
|---|---|---|
| 启用定时任务 | — | 勾选后需点「启动」才会运行 |
| 间隔 | 1–1440 分钟 | 两次执行之间的间隔 |
| 单批数量 | 1–1000 | 单轮最多上传数，防止打爆网络 |
| 失败重试次数 | 0–10 | 超过后标记为「上传失败」 |

「启动」「停止」即时控制调度线程；配置保存后若已启用会自动重启调度使新间隔生效。

### 3.3 生成产物管理

显示全部生成记录：文件名、大小、包含尺寸、上传状态、创建时间。

| 状态 | 含义 |
|---|---|
| 待上传 | 已存本地，尚未推送对象存储 |
| 已上传 | 推送成功 |
| 上传失败 | 超过重试次数仍未成功，鼠标悬停可看错误原因 |

操作：

- **下载**：按 ID 取回原始 ICO 文件
- **上传**：单个重试

## 4. 命令行

### 4.1 查看配置

```bash
icogen info
```

输出当前配置、输出目录、服务地址、可用尺寸预设。

### 4.2 环境自检

```bash
icogen doctor
```

报告 Pillow 版本、输出目录可写性、可选依赖状态（tkinterdnd2 / ttkthemes / cairosvg）、
尺寸配置合法性与支持的输入格式。发现阻断性问题时退出码为 `1`，
适合放在 CI 或部署脚本最前面，先确认环境再跑生成。

### 4.3 转换

```bash
# 单文件
icogen convert logo.png -s 16,32,48,256

# 指定输出目录
icogen convert logo.png -o /tmp/out

# 批量目录（仅处理支持的图片格式）
icogen convert ./images/ -s 16,32,48,256

# 批量目录 + 递归扫描子目录（同名文件输出自动加哈希后缀，不会互相覆盖）
icogen convert ./images/ --recursive -s 16,32,48

# 额外输出独立 PNG（应用开发常用尺寸集）
icogen convert logo.png --png-sizes 16,32,256 -s 16,32,48

# PNG 帧编码：同等画质体积更小（旧系统如 Windows XP 不识别）
icogen convert logo.png --bitmap-format png -s 16,32,48

# 站点物料包与 ICO 一起产出
icogen convert logo.png --site-assets --app-name "My App" --theme-color "#0e7d68"

# 内容留白：主体缩到画面 90% 居中
icogen convert logo.png --padding 0.1 -s 16,32,48

# 非正方形处理策略
icogen convert wide.jpg --fit contain -s 16,32,48

# PWA 安全区：内容缩到中心 60%
icogen convert logo.png --fit maskable --safe-zone 0.6 -s 192,512

# contain 模式用不透明底色补边
icogen convert wide.png --fit contain --background "#112233" --pad-opaque -s 32

# 混合格式尺寸写法
icogen convert logo.png -s 16x16,32x32,48x48

# 预演：只报告体积与警告，不写盘
icogen convert logo.png --dry-run -s 16,32,48,256
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `-s, --sizes` | 尺寸列表 | `16,32,48,256` |
| `-o, --output-dir` | 输出目录 | 配置中的 `output_dir` |
| `--fit` | cover / contain / maskable / stretch | `cover` |
| `--safe-zone` | maskable 模式安全区比例，0.5–1.0 | `0.8` |
| `--padding` | 内容留白比例（cover/contain），0–0.6 | `0` |
| `--background` | 留白填充色，6 位十六进制 | `#ffffff` |
| `--pad-opaque` | 留白使用不透明底色（默认透明留边） | 关闭 |
| `--recursive` | 目录输入时递归扫描子目录 | 关闭 |
| `--png-sizes` | 额外输出独立 PNG，尺寸逗号分隔，1–1024 | 关闭 |
| `--bitmap-format` | ICO 帧编码格式：bmp（最大兼容）/ png（体积更小） | `bmp` |
| `--site-assets` | 同时输出完整站点物料包 ZIP | 关闭 |
| `--no-maskable` | 站点物料包不含 maskable 变体 | 关闭 |
| `--app-name` | 站点物料包 manifest 应用名 | `My App` |
| `--theme-color` | 站点物料包主题色 | `#ffffff` |
| `--merge-manifest` | 既有 manifest.json 路径：只合并 icons 条目 | 关闭 |
| `--dry-run` | 预演：生成到内存并报告体积与警告，不落盘 | 关闭 |
| `--config` | 指定配置文件 | 默认路径 |

退出码：`0` 至少一个成功，`1` 全部失败。

`--background` 与 `--safe-zone` 的非法值在**生成前**就会失败并给出原因，
不会产出不可用的结果。`--dry-run` 除了报告体积，还会把 warning 级别的质量提示一并打印，
用于在批量生成前判断是否值得换源图。

```bash
icogen -v serve          # 开启 DEBUG 日志
```

## 5. 对象存储上传流程

```
生成 ICO
   ↓
写入本地目录（icons/），状态 pending
   ↓
上传触发（手动点「上传」/「立即上传全部待传」，或定时任务到点）
   ↓
签名 PUT → 对象存储
   ├─ 成功 → 状态 uploaded，记录对象键
   └─ 失败 → 尝试次数 +1
        ├─ 未超重试上限 → 保持 pending，等下一轮
        └─ 超过上限 → 状态 failed，可手动重试
```

## 6. iOS / Android 启动图（PWA splash screen）

站点物料包**不包含**启动图，这是有意的取舍，理由见本节末尾。此处给出完整尺寸清单与
media 查询模板，需要时可自行生成后放入站点。

### 6.1 尺寸清单

iOS 用 `<link rel="apple-touch-startup-image">` 声明，每条都要配 media 查询。
下表为常用设备尺寸（Apple 已从人机界面指南中删除该表，以下为社区流传版本，
使用前建议按目标设备核对）：

| 设备 | 图片尺寸 | media 查询 |
|---|---|---|
| iPhone SE / 6/7/8 | 750×1334 | `(device-width: 375px) and (device-height: 667px) and (-webkit-device-pixel-ratio: 2) and (orientation: portrait)` |
| iPhone 8 Plus | 1242×2208 | `(device-width: 414px) and (device-height: 736px) and (-webkit-device-pixel-ratio: 3) and (orientation: portrait)` |
| iPhone X / 11 Pro | 1125×2436 | `(device-width: 375px) and (device-height: 812px) and (-webkit-device-pixel-ratio: 3) and (orientation: portrait)` |
| iPhone 12/13 | 1170×2532 | `(device-width: 390px) and (device-height: 844px) and (-webkit-device-pixel-ratio: 3) and (orientation: portrait)` |
| iPhone 14 Pro | 1179×2556 | `(device-width: 393px) and (device-height: 852px) and (-webkit-device-pixel-ratio: 3) and (orientation: portrait)` |
| iPhone 14 Pro Max | 1290×2796 | `(device-width:  430px) and (device-height: 932px) and (-webkit-device-pixel-ratio: 3) and (orientation: portrait)` |
| iPad（9.7 / Air） | 1536×2048 | `(device-width: 768px) and (device-height: 1024px) and (-webkit-device-pixel-ratio: 2) and (orientation: portrait)` |
| iPad Air 10.5 / Pro 10.5 | 1668×2224 | `(device-width: 834px) and (device-height: 1112px) and (-webkit-device-pixel-ratio: 2) and (orientation: portrait)` |

横屏需把 `orientation: portrait` 改为 `landscape`，并把宽高对调。

### 6.2 生成方式

启动图本质是「纯色或渐变背景 + 居中图标」，可用本项目现有的 contain 模式批量产出：

```bash
# 以 2048×2732 为例：contain 保留完整内容并居中，配不透明底色
icogen convert logo.png --fit contain --pad-opaque \
  --background "#ffffff" -s 2732 -o splash
```

注意 `-s` 只能是正方形，因此竖长图需先生成正方形底图再裁剪，或用任意图像工具补边。
Android 侧不需要启动图文件，manifest 里的 `icons` 已覆盖。

### 6.3 为什么不自动生成

三条理由，按权重排序：

1. **体积代价不对称**。十余张启动图合计数 MB，而站点物料包本身只有数十 KB。
   把两者绑在一起，会让「只想下个 favicon」的用户白背数 MB 流量。
2. **规格会漂移**。Apple 已从人机界面指南删除设备尺寸表，等于把维护责任转给工具方；
   一旦内置表过期，产出的是错尺寸文件，比不生成更难排查。
3. **浏览器匹配失败是静默的**。media 查询写错时 iOS 直接显示白屏，不会报错，
   自动生成反而把错误扩散到更多文件。

结论：把清单与模板写进文档（零成本、可核对），生成留给确有需求的场景。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| ICO 最大 256×256 | 格式规范限制，选择更大尺寸会被拒绝并提示 |
| 网页版站点物料包需令牌 | 与桌面版行为一致；仅合并 ICO 无需令牌 |
| 定时任务随服务进程 | 服务停止则调度停止，不做系统级托管 |
| 对象存储需手动配置 | 未配置时完全本地运行，不自动上传 |
| 动图取单帧 | ICO 不支持动画，取指定帧（默认首帧） |
| SVG 需可选依赖 | 未安装 cairosvg 时给出明确提示，不影响其他格式 |
