# 01 · 项目介绍与架构

> 适用版本：**v0.1.0**

## 1. 项目概述

IcoGenerator 是一个多尺寸 ICO 图标生成器。它把常见的图片（JPG / PNG / GIF / BMP / WebP / TIFF / ICO / SVG）转换为包含多个分辨率的 ICO 文件，用于网站 favicon 与应用程序图标。

项目提供四套入口，**共用同一套核心引擎**，因此在任何入口下，同样的输入都会得到字节一致的输出：

| 形态 | 启动方式 | 适用场景 |
|---|---|---|
| 桌面版 GUI | `icogen desktop` | 单机日常使用，支持拖拽 |
| 本地网页版 | `icogen serve` → 访问 `/app` | 浏览器操作、批量处理 |
| 管理控制台 | `icogen serve` → 访问 `/admin` | 管理员配置对象存储、查看产物 |
| 命令行 | `icogen convert` | 服务器、脚本、CI 流水线 |

## 2. 核心设计原则：本地优先

这是 v0.1.0 最重要的设计决策，直接来自对旧版缺陷的复盘。

旧版桌面版在**每次用户选择图片时，会自动把图片上传到第三方图床**，且 uid/token 明文硬编码在源码里。用户既不知情，也无法关闭；一旦源码泄露，凭据即失效。

v0.1.0 改为本地优先模型：

```
用户生成 ICO
     │
     ▼
写入本地目录  ← 真相源，到此为止前台功能已完整可用
     │
     ▼
（可选）管理员配置对象存储后，手动或定时上传
```

带来三个结果：

1. **不配置对象存储也能 100% 使用**——生成、导出、打包都不依赖网络；
2. **上传失败不影响使用**——本地文件始终完整；
3. **用户图片不会在无感知的情况下离开本机**。

## 3. 模块结构

```
src/icogenerator/
├── core/                  纯逻辑层：零 GUI、零网络、零磁盘写入
│   ├── errors.py          统一异常体系（所有可预期错误继承 IcogenError）
│   ├── imaging.py         解码、EXIF 方向纠正、色彩模式规范化、正方形适配、SVG 栅格化
│   ├── icons.py           ICO 编码（合并 / 逐尺寸）
│   ├── assets.py          站点物料包（ICO + apple/android/mstile/manifest + MANIFEST）
│   └── quality.py         分级质量提示（level / code / message）
│
├── config.py              配置与凭据：优先级、原子写入、权限收紧、脱敏
├── storage.py             本地存储：文件名净化、路径穿越防护、原子写入、元数据
├── uploader.py            S3 兼容上传：标准库实现 SigV4 签名，零第三方依赖
├── queue.py               上传队列：线程安全、失败重试、定时调度
├── server.py              本地 HTTP 服务 + API + 管理控制台后端
├── desktop.py             桌面版 GUI（Tkinter）
├── cli.py                 命令行入口
└── web/                   前端资源
    ├── index.html / admin.js / style.css    管理控制台
    ├── client.html / client.js / client.css 网页版生成器
```

### 分层原则

`core/` 不 import 任何 GUI、网络、磁盘模块。这带来三个好处：

- **可测试**：核心逻辑无需启动窗口或网络即可测试；
- **一致**：桌面版与网页版不会因为各自实现而产出不同结果；
- **可复用**：CLI、HTTP 服务、GUI 都能直接调用同一套核心实现。

## 4. 关键模块职责

### 4.1 core/imaging.py — 图像解码与规范化

集中处理四类真实缺陷的修复：

1. **CMYK / 多通道源图**：统一转为 RGBA，消除 `cannot write mode CMYK as PNG` 崩溃；
2. **非正方形源图**：提供四种适配策略，避免强行拉伸变形；
3. **动图**：显式定位到目标帧（默认首帧），最多取 8 帧；
4. **超大像素图（解压炸弹）**：解码前检查单边像素上限（8192）与总像素上限（约 1.69 亿），拒绝恶意大图。

支持的输入格式：`.jpg` `.jpeg` `.png` `.gif` `.bmp` `.webp` `.ico` `.tif` `.tiff` `.svg`（SVG 需可选依赖 cairosvg）。

### 4.2 core/icons.py — ICO 编码

修复旧版最致命的缺陷。Pillow 的 ICO 插件有两条独立约束：

1. **不能用 `save_all=True`** —— ICO 未注册进 `SAVE_ALL`，Pillow 10+ 会抛 `KeyError: 'ICO'`；
2. **基准图不能小于最大目标尺寸** —— 插件会**静默跳过**所有更大的尺寸，且不报任何错。

本模块的处理方法：

- 改用 Pillow 官方支持的 `sizes=[...]` 参数，一次 save 写入全部尺寸；
- 先把基准图升采样到**最大目标边长**，再交给 Pillow；
- 编码后**回读实际尺寸**校验，缺失则抛异常，绝不交付残缺 ICO。

内置 5 套尺寸预设：

| 预设 | 尺寸 |
|---|---|
| favicon | 16 / 32 / 48 |
| windows | 16 / 24 / 32 / 48 / 64 / 256 |
| full | 16 / 24 / 32 / 48 / 64 / 128 / 256 |
| small | 16 / 32 |
| mobile | 48 / 64 / 128 / 256 |

### 4.3 core/assets.py — 站点物料包

一次输入，产出可直接投入使用的完整站点物料（13 个文件）：

```
favicon.ico                        多尺寸 ICO（浏览器 / Windows）
favicon-16x16.png                  浏览器标签（标准 DPI）
favicon-32x32.png                  浏览器标签（HiDPI）
apple-touch-icon.png               iOS 主屏（180）
android-chrome-192x192.png         Android 自适应图标
android-chrome-512x512.png         PWA 安装 / 启动画面
android-chrome-512x512-maskable.png PWA 安全区变体
mstile-150x150.png                 Windows 磁贴
browserconfig.xml                  Windows 磁贴配置
manifest.json                      PWA Web App Manifest
site-icon.html                     可直接粘贴的 HTML 引用片段
MANIFEST.txt                       自说明清单（文件用途 + 生成参数）
```

### 4.4 core/quality.py — 分级质量提示

每条提示携带三个字段：`level`（success / warning / error / info）、`code`（稳定机器标识）、`message`（面向用户文案）。界面层只按级别着色展示，前端按 `level` 分流，不匹配中文文案——文案可改，`level` 与 `code` 稳定。

覆盖的判据：

| 级别 | 触发条件 |
|---|---|
| warning | 源图小于目标尺寸需放大；源图无透明通道；单边或总像素逼近解码上限；选中尺寸超过 4 个；ICO 超过 32KB 软预算 |
| info | ICO 体积达到软预算的 80% |
| success | 以上都不命中，给出源图尺寸与透明通道结论 |

### 4.5 config.py — 配置与凭据管理

- **源码内不存放任何密钥**。access_key / secret_key 只存在于用户配置文件中；
- 配置文件写入时原子操作（临时文件 + `os.replace`），POSIX 下权限收紧为 `0600`；
- 读取配置时对敏感字段做脱敏，绝不写进日志；
- 配置文件缺失时自动生成默认配置，不崩溃；
- 配置优先级：显式参数 > 环境变量 > 配置文件 > 默认值。

### 4.6 storage.py — 本地存储

生成结果的**真相源**。目录结构：

```
<root>/
    icons/      生成的 ICO / PNG
    bundles/    打包的 ZIP
    .icogen/    元数据（index.json）
```

安全措施：

- **文件名净化**：剥离目录分隔符、去除控制字符、仅保留 `[A-Za-z0-9._-]`、扩展名白名单（`.ico` / `.png` / `.zip` / `.json`）；
- **路径穿越防护**：解析后越界检查，任何越出根目录的路径直接拒绝；
- **原子写入**：临时文件 + `os.replace` + `fsync`，杜绝半截文件；
- **SHA-256** 校验值记录，便于校验完整性。

### 4.7 uploader.py — S3 兼容上传

用**标准库**实现 AWS Signature V4 签名，无需 boto3 / requests。支持阿里云 OSS / 腾讯云 COS / 华为云 OBS / MinIO / AWS S3 / Cloudflare R2。

安全措施：

- 密钥只从内存中的配置读取，**绝不写入日志**；
- 上传走**受限 opener**：仅注册 HTTP / HTTPS 与重定向护栏，FTP / File / Data 等面整体关闭；
- 重定向目标协议二次校验，仅放行 http / https；
- 固定 Content-Type 白名单，不从用户输入推导，避免头部注入。

### 4.8 queue.py — 上传队列

- 前台生成流程只写本地，从不等待网络，上传失败不影响用户使用；
- 手动上传与定时上传共用同一队列，避免并发重复上传同一文件；
- 指数退避重试，超过重试次数标记为「上传失败」；
- 定时调度使用 `Event.wait()` 而非 `sleep`，停止能立即响应。

### 4.9 server.py — 本地 HTTP 服务

基于标准库 `ThreadingHTTPServer`，无 Web 框架依赖。安全设计：

- 默认仅绑定 `127.0.0.1`，不监听外网；
- 管理接口**始终**要求 Bearer 令牌（**不因绑定回环而放宽**）；
- 前台 `/api/generate` 无需令牌，但只写本地磁盘、不改配置；
- CSRF 防护：校验 `Origin` + 强制 `application/json`；
- 请求体大小上限（20MB），防止内存耗尽。

### 4.10 desktop.py — 桌面版 GUI

Tkinter 实现，支持拖拽（可选 tkinterdnd2）、现代主题（可选 ttkthemes）。所有生成逻辑调用核心引擎，与网页版结果完全一致。

## 5. 技术选型理由

| 选择 | 理由 |
|---|---|
| 运行时仅依赖 Pillow | 对象存储改用标准库实现 SigV4 后，requests 不再需要，减少供应链面 |
| S3 签名手写而非 boto3 | boto3 带来数十个传递依赖；本项目只需 `PUT` 一个对象，标准库足够 |
| `http.server` 而非 Flask/FastAPI | 本地工具不值得引入 Web 框架；标准库可满足且零依赖 |
| Tkinter 而非 Electron | 桌面版要轻量、离线可用 |

## 6. 版本一致性

版本号 `0.1.0` 在三处声明，升级版本时需同时修改：

- `pyproject.toml` → `version = "0.1.0"`
- `src/icogenerator/__init__.py` → `__version__ = "0.1.0"`
- `src/icogenerator/server.py` → `VERSION = "0.1.0"`
